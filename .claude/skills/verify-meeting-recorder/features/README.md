# Meeting Recorder 검증 지도

이 폴더가 Meeting Recorder 화면 동작을 검증하는 기준이다. 조작 전에 이 색인을 읽고, 맞는 기능 파일을 따라 한다. 흐름 파일은 `../journeys/*.json`, 도구는 `scripts/dev/verify/drive.js`.

## 기본 전제

- `node scripts/dev/verify/doctor.js`가 `점검 통과`.
- 가짜 API와 임시 예시 회의로만 띄운다(`drive.js`가 만든다). 실제 녹음 폴더·설정·설치된 앱은 조작하지 않는다.
- 예시 회의: 제목 "예시 회의: 배포 일정 정리", 화자 2명, 30분. 확인 필요 남은 4개(r1 오인식 `랩캐시도`→추정 `Memcached`, r2 오인식 `화요일` 추정 없음, r3 이름 `도윤님` 녹취에 없음, r4 근거 확인) + 처리함 2개(r5 고침 `큐에이→QA`, r6 그대로 둠). 용어 `QA`(확인)·`알림`(추정). 할 일 2개(둘 다 안 함).

## 조작 규칙

- 흐름은 기본 상태에서 시작한다. 실행마다 예시 회의를 새로 만든다.
- 이름(aria-label·화면 글자)과 역할(탭·버튼·링크)로 찾는다. 클래스·DOM 위치·좌표로 찾지 않는다.
- 단축키는 진짜 키(`key`)로. JS로 값을 넣는 건 입력칸 키 처리기 버그를 못 잡는다.
- 글자는 그대로 쓴다. 따옴표 안의 이름을 바꾸지 않는다.

## 증거와 건너뜀 보고

- 사용자 동작과 그 결과 상태를 같이: 스냅샷 + 본체 호출(`expect.called`) + 파일이 바뀌는 기능은 파일(`expect.file`).
- 증거마다 흐름 이름이 폴더 이름에 붙는다(`verify-runs/<시각>-<흐름>/`).
- 닿지 못한 길은 시도한 단계와 모자란 전제를 적는다. 다른 길로 확인한 것을 그 길로 확인했다고 하지 않는다.

## 기능 파일 형식

H1 제목, 사용자가 보는 동작 한 문단, 그리고 H2 넷을 이 순서로: `Sub-features`(짧은 id와 한 줄), `How to get to it (user POV)`(진입점 전부), `Driving it with drive.js`(`Preconditions:`로 시작, 동작·단계·보이는 결과를 짝지은 줄), `Gotchas`. 구현 설명은 넣지 않는다.

## 기능

- [확인 필요](./review.md) — 적용(추정·직접 입력)·확인됨·그대로 두기·여러 개·되돌리기·다시 열기·확인 마치기. 흐름 `review-apply`
- [회의 페이지](./meeting-page.md) — 탭·⌘F·화자 이름·할 일·용어·… 메뉴. 흐름 `meeting-basics`
- [회의 목록](./meetings-list.md) — 갈래·검색·넘침·바로가기·회의 열기. 흐름 `meetings-list`
- [질문으로 찾기](./ask.md) — 둥근 버튼·조건 칩·기간 충돌·알림·질문 탭·실패. 흐름 `ask`
- [녹음 압축](./compress.md) — 확인을 마친 회의의 안내·압축·그대로 두기·… 메뉴. 흐름 `compress`
- [녹음 파일 가져오기](./import.md) — 파일 고르기·확인 창·가져오기. 흐름 `import`
- [처음 설정](./onboarding.md) — 단계 이동·저장. 흐름 `onboarding`
- 통계 (React) — 위 칸 숫자, 14일 막대(마우스 올리면 그날 글자 수·횟수), 앱·언어 막대. 흐름 `stats` (가짜 통계: 마지막 날 130자·13회)
- 사전 (React로 옮긴 첫 화면) — 쉼표로 여러 개 추가(겹치면 뺌)·지우기·사이드바 단어 수. 흐름 `dictionary`. 함정: 아래 도움말에 `"PJY"`라는 글이 있어 `noText: "PJY"`로는 지운 걸 확인할 수 없다 — 저장 호출로 본다

아직 지도에 없는 것(다음에 더할 것): 받아쓰기 기록(복사·다시 붙여넣기·지우기·검색·이어 받기), 설정, 홈, 통계, 흐름도(만들기·채팅·SVG), 액션, 구간 다시 받아쓰기. 이 기능들은 `scripts/dev/feature-test.js`·`ui-test.js`가 회귀 시험으로 다룬다.
