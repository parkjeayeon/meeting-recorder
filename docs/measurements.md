- 지어낸 회의는 정해진 문장을 돌려써서 단어 검색이 실제보다 극단적으로 나온다(다 맞거나 다 틀림). 실제 회의는 5개뿐이라 참고만.

## 받아쓰기 언어: 고정 vs 자동 감지 (2026-11-07)
macOS `say`(Yuna·Samantha)로 만든 소리를 16kHz로 바꿔, 앱이 띄운 Whisper 서버(large-v3-turbo q8)에 `language=ko`와 `language=auto`로 보냈다 (`verbose_json`의 감지 언어 확인).

| 소리 | `ko` 고정 | 자동 감지 |
|---|---|---|
| 한국어 문장 | 그대로 | 그대로 (korean) |
| 한국어 + 영어 용어 ("API 서버 레이턴시가 높아서 레디스 캐시를…") | 그대로 | 그대로 (korean) |
| 영어 문장 | 엉뚱한 한국어 ("이제 새로운 새로운 스튜디오에서…") | 그대로 (english) |
| 짧은 "네" | "네." | **"Đề."** (vietnamese) |
| 영어 문장 → 한국어 문장 | 영어 문장 빠짐 | 영어 문장 빠짐 (korean) |
| 한국어 문장 → 영어 문장 | 영어 문장 빠짐 | 영어 문장 빠짐 (korean) |

- Whisper는 요청 하나에 언어 하나를 정한다(자동이면 앞부분으로). 그래서 자동은 말 하나가 한 언어일 때만 낫고, 아주 짧은 말은 엉뚱한 언어로 잡히며, 문장 단위로 언어가 섞이면 한쪽이 사라진다. 한 문장 안에 섞인 영어 용어는 고정에서도 괜찮다.
- 회의는 약 10분 조각마다 요청 하나라, 자동이면 조각 앞부분으로 그 조각 전체의 언어가 정해진다.
- Wispr Flow는 "쓰는 언어 목록(여러 개) + 자동 감지"로 하고 받아쓰기 막대의 언어 선택기를 없앴다(앱 코드 조사). 그들 서버는 목록 안에서 감지하지만, Whisper 서버는 후보를 목록으로 좁힐 수 없다 → 이 앱은 언어를 고르는 쪽으로 둔다 (결정 54).

### 후보를 한국어·영어·일본어로 좁힌 자동 (2026-11-07, 결정 55)
같은 소리를 앱의 `transcribe`(자동)로: 한국어 문장 → ko 0.76초, 영어 문장 → en 0.70초, 한국어+영어 용어 → ko 0.71초, 짧은 "네"(말소리 0.4초) → 감지 없이 ko "네." 0.23초. 같은 "네"를 말소리 3초로 속이면 vi로 감지 → 후보 중 ja로 다시 받아써 "で、"(0.94초) — 짧은 말을 첫 언어로 두는 이유. 영어+한국어 문장 이어 말하기는 여전히 한국어 문장만.

## 받아쓰기 기록이 많을 때 (2026-11-07, 결정 56)
지어낸 기록 2만 개(`dictations.jsonl` 18.4MB)로 `src/core/dictlog.mts`: 읽기(파싱·정렬) 37ms, 한 묶음(30개) 0.1ms, 전체 찾기 21ms, 통계 7ms (처음엔 345ms — 앱별 시간을 기록마다 배열 복사로 모았다). 본체는 파일 크기·수정 시각이 같으면 다시 읽지 않고, 통계는 파일이 바뀌거나 날이 바뀔 때만 다시 센다.


## 회의 녹음 압축(AAC) 전후 받아쓰기 (2026-11-07)
실제 회의(2시간 5분, 48kHz 모노 WAV 689MB)의 사본에서 10분 구간 두 개(평범한 구간 A, 유실 항목이 있는 구간 B)를 WAV · AAC 96kbps · AAC 64kbps로 만들고, 앱과 같은 조건(회의용 large-v3 서버 `-sns -pp`, 16kHz, ko, temperature 0, 사전 힌트)으로 받아썼다. 사본은 측정 뒤 지웠다.

| | 크기(10분) | 반복 조각 (A / B) | 반복을 뺀 글자 수 (A / B) |
|---|---|---|---|
| WAV 원본 | 57.6MB | 7 / 8 | 2873 / 2518 |
| WAV 1샘플 밀기 (귀로 구분 불가) | 〃 | 2 / 5 | 1971 / 2787 |
| WAV 2샘플 밀기 | 〃 | 2 / 17 | 1971 / 2902 |
| AAC 96kbps | 7.2MB (1/8) | 3 / 4 | 2694 / 2443 |
| AAC 96kbps + 1샘플 | 〃 | 7 / 0 | 2662 / 4476 |
| AAC 64kbps | 4.9MB (1/12) | **62 / 162** | 2246 / 1587 |
| AAC 64kbps + 1샘플 | 〃 | **62 / 15** | 2246 / 2339 |

- 같은 파일은 매번 글자 하나까지 같은 결과(결정적). 하지만 귀로 구분할 수 없는 1샘플 이동에도 결과가 크게 달라진다 — 원본 대비 글자 차이 46~58%, 구간 A는 내용이 약 30% 줄었다. 원본 한 번의 결과를 '정답'으로 볼 수 없어, 같은 원본의 흔들림 폭과 비교했다.
- **AAC 96kbps는 원본의 흔들림 폭 안**(반복 0~7, 글자 수도 원본 변형들 사이). **64kbps는 반복 고장이 크게 는다**(62·162, 밀어도 62) — 쓰지 않는다.
- 2시간 전체: AAC 96kbps 만들기 11초, 689MB → 85MB(1/8). 다시 16kHz WAV로 풀기 1초(회의록 다시 만들기·구간 다시 받아쓰기 앞에 붙는 시간).
- 덤으로 드러난 것: 회의 녹취는 입력이 아주 조금만 달라도 결과가 크게 달라질 만큼 불안정하다(앞 문장을 이어 받는 Whisper의 성질). 압축과 별개로 볼 일이다.
