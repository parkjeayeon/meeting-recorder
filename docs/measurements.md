## 질문으로 회의 거르기 (2026-11-06, Codex, `scripts/dev/eval/search-eval.mjs`)
지어낸 회의 60·300개(2024~2026, 주제 12개, 40%는 돌려 말함, 30%는 녹취에만 곁다리 언급) + 실제 회의 5개, 질문 24개(날짜 4·주제 6·돌려 말하기 4·날짜+주제 4·상태 2·실제 회의 4). 질문별 결과·LLM 호출 기록은 `eval-runs/`(git 제외, 실제 회의 내용이 들어감), 실행마다 `eval-runs/history.csv`에 쌓인다.

|---|---|---|---|---|---|---|---|
| M0 단어 검색 (LLM 없음) | 300 | 55% | 31% | 0.37 | 13% | 0 | 0초 |

- Codex는 부를 때마다 기본 입력 약 16,700토큰(질문과 상관없음, 대부분 캐시). 두 측정 전체(호출 약 450번)로 Codex 주간 사용 16% → 19%.

- M2 1차가 흔한 주제 질문("장애 회고 회의")에서 약했던 건 LLM 판단이 아니라 찾을 말이 기술 용어로만 나와 말로 한 회의("서비스가 멈췄던 거")가 후보에 들지 못해서였다 → 찾을 말에 회의에서 실제로 하는 말투를 절반 섞게 하자 F1 0.79 → 0.91.

- **Codex 기본 입력 약 16,600토큰의 구성** (같은 모델에 "OK" 한 줄, 하나씩 빼며 잼): Codex 자체(기본 지시문·내장 도구 정의·환경 정보) 약 14,300 — 설정으로 못 바꿈 / 켜 둔 플러그인 14개와 MCP 서버 약 1,700 / 스킬 6개의 이름·한 줄 설명 약 570(본문은 안 들어감) / 사용자 규칙 `~/.codex/AGENTS.md`는 비어 있어 0(적으면 부를 때마다 전부 들어감). Claude Code는 앱처럼 부르면 약 530~580토큰.
- SQLite FTS5 trigram은 3글자 이상만 찾는다. 두 글자 한국어("장애", "채용")는 LIKE로 따로 찾아야 한다.
- 지어낸 회의는 정해진 문장을 돌려써서 단어 검색이 실제보다 극단적으로 나온다(다 맞거나 다 틀림). 실제 회의는 5개뿐이라 참고만.
